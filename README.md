# ICM Edge Extension

Microsoft Edge Manifest V3 扩展，为 ICM 事件表格增加个人处理标签列，支持通过浏览器账号跨设备同步。

## 功能
- 自动在 ICM 表格中添加“Tag”列。
- 每个事件可以选择零个或一个 Tag（未标记或用户自定义 Tag）。
- Case 详情页（`/imp/v5/incidents/details/{Incident ID}/summary` 等详情子页面）右下角显示当前 Tag 按钮，点击即可单选处理状态或恢复“未标记”，也可新建、重命名、改色和删除 Tag。
- 详情页与列表使用同一份 Tag 数据，跨标签页自动更新；页面内切换到另一个 case 时，按钮也会切换到对应事件。Tag 仅用于个人处理状态记录，不会修改 ICM 官方状态。
- 从 Case 返回缓存的 Search 列表时，已有 Tag 列也会重新同步；搜索、分页复用表格行时，Tag 按当前行的 Incident ID 读取和保存。
- 从表头的 Tag 筛选菜单中可以动态创建新的 Tag，系统会自动分配高对比度颜色。
- 可以在菜单中使用颜色选择器（`input[type="color"]`）修改任何 Tag 的颜色。
- 可以在菜单中重命名或删除 Tag；删除前会确认，关联事件随后显示为“未标记”。
- 表头支持动态列出“未标记”和所有用户创建的 Tag 进行多选筛选，支持全选、清空。
- 使用 Incident ID 关联并以独立记录保存到 `chrome.storage.sync`，各页面及符合条件的设备间 Tag、名称、颜色和事件标记会自动同步。
- 兼容 Kendo 动态表格渲染和弹出菜单边界问题。
- 扩展不直接请求 ICM 或其他服务器；同步数据由浏览器通过其账号同步服务传输。

## 安装方法
1. 在 Edge 地址栏打开 `edge://extensions/`。
2. 开启“开发人员模式”。
3. 点击“加载解压缩的扩展”。
4. 选择包含 `manifest.json` 的扩展目录。
5. 打开或刷新 `https://portal.microsofticm.com/` 页面，表格中会自动出现“Tag”列。
6. 已安装的扩展更新后，在扩展管理页点击“重新加载”，再刷新 ICM 页面；打开具体 case 后，右下角会出现当前 Tag 按钮。

## 数据保存
### 开启账号同步
1. 在各设备的 Edge 浏览器个人资料中登录同一账号，并在个人资料的“同步”设置中开启同步及扩展同步。Chrome 同理；Edge 与 Chrome 的账号同步服务不互通。
2. 在各设备安装具有**相同扩展 ID** 的本扩展。可在扩展管理页查看 ID。仅复制目录并分别“加载解压缩的扩展”不保证 ID 相同，不能据此保证跨设备同步；稳定分发建议使用同一商店条目或固定扩展身份的分发方式。
3. 更新后重新加载扩展并刷新 ICM 页面。同步由浏览器异步完成，不保证即时到达；企业策略可能限制账号同步。

这里使用的是**浏览器个人资料账号**，不是 ICM 网页登录账号。扩展无需读取密码、Cookie 或申请额外登录权限；它也不会自动开启浏览器同步。未启用浏览器同步时，数据仍可在当前设备使用，但不会上传到其他设备。

### 现有数据迁移
首次成功启动新版时，将旧 `chrome.storage.local` 中的 Tag 和事件标记复制到同步存储；同名键已存在时以同步存储中的记录为准，已删除的云端 Tag 不会被旧名称或颜色恢复。迁移成功后本机记录一次性完成标记，后续不再导入旧数据，避免已取消的标记复活。原本地数据保留为备份，但不再随编辑更新。迁移失败时不标记完成，并提示错误；刷新页面可重试，不会静默切换为本地保存。

### 容量与隐私
`chrome.storage.sync` 的限制包括总量约 100KB、每条约 8KB、最多 512 条记录，以及每分钟/每小时写入次数限制。目前每个 Tag 使用 3 条记录，每个事件标记使用 1 条；删除的 Tag 留有删除标记，取消事件标记也会保留记录。大量历史事件可能耗尽容量，不能当作无限存储。创建、重命名、改色、删除及事件标记写入失败时会明确提示。

同步内容包括 Tag 名称、颜色及 Incident ID 与 Tag 的关联，请先确认符合组织的数据处理要求。浏览器同步存储不是加密机密存储，不要在 Tag 中保存敏感信息。不要将卸载扩展视为备份或清理云端数据的方式。

### 保存失败排查
- 更新后先在扩展管理页“重新加载”，然后刷新**所有已打开的 ICM 页面**。旧页面中的脚本可能因扩展重载而失效，报 `Extension context invalidated`；这不表示账号同步容量已满。
- 错误弹窗会显示“具体错误”及对应建议。`MAX_WRITE_OPERATIONS_PER_MINUTE` 表示需停止操作至少一分钟后重试；`QUOTA_BYTES_PER_ITEM` 表示单条记录过大；`QUOTA_BYTES` 或 `MAX_ITEMS` 表示总容量或记录数已满，单纯刷新不能解决。
- 若仍失败，请提供弹窗中的“具体错误”，或在当前 ICM 页按 F12，在 Console 中查看 `Failed to save incident Tag` / `Failed to sync Tag change` 后面的错误。不要通过卸载扩展或清空存储排查，以免丢失数据。

## 回归测试
安装 Node.js 后运行 `node --test content.test.js`。测试覆盖缓存列表恢复、表格行复用、同步事件刷新、旧数据一次性迁移、云端冲突与删除标记、迁移失败重试及保存失败恢复，无需安装依赖。测试使用模拟存储；实际账号跨设备同步仍需在上述配置满足后，用两台设备手动验证。
